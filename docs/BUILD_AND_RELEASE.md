# Build & Release

How versions are built, shipped and updated.

## Versioning

The app version is defined once in `app.json` for the shippable version and per
platform build numbers:

| Field | File | Current |
| --- | --- | --- |
| `expo.version` | `app.json` / `package.json` | `3.0.0` |
| `expo.ios.buildNumber` | `app.json` | `6` |
| `expo.android.versionCode` | `app.json` | `15` |

`eas.json` sets `appVersionSource: "local"` and `autoIncrement: false`, so
**bump these by hand** before a store build.

## Android releases (Jenkins)

Android releases are built and published by Jenkins, **without EAS**. The
release job produces the same artifact set as the historical GitHub releases,
all signed with the Play upload key:

- `animu-<version>-code<versionCode>.aab` — Play Store upload
- `animu-<version>-code<versionCode>.apk` — universal direct-install (all ABIs)
- a `.sha256` file for each
- `RELEASE_NOTES.md` — artifact table, SHA-256s, and per-device Play download
  sizes

### Jobs

| Job | Jenkinsfile | Purpose |
| --- | --- | --- |
| `animu-mobile-app` | `Jenkinsfile` | CI: typecheck, lint, Expo SDK alignment, dependency audit, `vitest`, animu-api checks, Android bundle smoke test, React Doctor ≥ 85. |
| `animu-mobile-app-release` | `Jenkinsfile.release` | Parameterized release build (below). |

Both run on the `animu-android-native` host agent (Node, JDK 17, Android
SDK/NDK). The release job is parameterized:

| Parameter | Meaning |
| --- | --- |
| `VERSION` | Marketing version; must equal `app.json` → `expo.version`. |
| `VERSION_CODE` | Android `versionCode`; must equal `app.json` → `expo.android.versionCode`. |
| `TAG` | Git/release tag, e.g. `v3.0.1`. |
| `CREATE_GITHUB_RELEASE` | When true, create the GitHub release and upload the artifacts. |
| `DRAFT` / `PRERELEASE` | Flags for the created GitHub release. |
| `TRUST_CI` | Skip the pre-release checks when the CI job has a passing build for the exact commit. |
| `CI_JOB_NAME` | CI job consulted by `TRUST_CI` (default `animu-mobile-app`). |

### Pipeline steps

1. Validate parameters and `app.json` (version/versionCode must match).
2. Checkout the repo **with submodules** (`packages/animu-api`, and the private
   `packages/react-native-airwave` with the `airwave-read-token` credential).
3. Install dependencies with pnpm — only when `pnpm-lock.yaml` changed (stamped).
4. `TRUST_CI`: if the CI job has a SUCCESS build for `HEAD`, the pre-release
   checks are skipped; otherwise they run (typecheck, lint, tests, React Doctor).
5. `expo prebuild --platform android` — only when `app.json` / `plugins` /
   lockfile / Airwave's config plugin changed (stamped). Otherwise the existing `android/` is reused so
   Gradle stays incremental.
6. Inject the release signing config (see below) and run
   `./gradlew :app:bundleRelease`.
7. Derive the universal APK from the AAB with **bundletool**
   (`--mode=universal`) instead of a second Gradle build.
8. Verify both artifacts are **not** signed with the Android debug key and that
   the APK signer matches the AAB signer.
9. Write SHA-256 checksums, per-device Play download sizes (bundletool), and
   `RELEASE_NOTES.md`.
10. Optionally create the GitHub release and upload the artifacts.

### Signing (Play uploads)

The Play upload keystore is stored in the Jenkins `android-upload-keystore`
credential and injected the same way EAS did it: a small Gradle script
(`scripts/inject-android-signing.mjs` → `android/app/ci-signing.gradle`) that
declares a `release` `signingConfig` and applies it to the release build type.
Keystore passwords are written to mode-600 files and passed to bundletool with
its `file:` scheme so they never appear in the build log.

The committed `android/app/build.gradle` still points `release` at the debug
keystore — that file is generated by `expo prebuild` (gitignored) and is never
what ships. Always verify an artifact before uploading:

```bash
keytool -printcert -jarfile app.aab   # must NOT be CN=Android Debug, O=Android, C=US
```

### Licensed fonts

The Proxima Nova fonts are gitignored. For releases they are staged on the
Jenkins host at `~/.animu-secrets/fonts/` and copied into `src/assets/fonts/`
by the pipeline. See [Development → Fonts](DEVELOPMENT.md#fonts).

### `packages/animu-api`

`packages/animu-api` is a git submodule consumed as a `file:` dependency
(symlinked into `node_modules`). Its `dist/` (ESM + CJS) is built by the app's
`postinstall` hook.

The library also has its own Jenkins job — **`animu-api`**
([RadioAnimu/animu-api](https://github.com/RadioAnimu/animu-api), `Jenkinsfile`)
— which typechecks, tests, builds, and archives `animu-api-dist.tar.gz` for each
commit.

The mobile release rebuilds `packages/animu-api` **only when the pinned
submodule commit changed**. When it does, it first tries to download the
prebuilt `dist/` from the `animu-api` job for that exact commit
(`scripts/fetch-animu-api-dist.mjs`) and falls back to building from source if
no successful build exists yet. An unchanged pin reuses the existing `dist/`.

### `packages/react-native-airwave`

The audio player is a private git submodule consumed from source (see
[Development → Player library](DEVELOPMENT.md#player-library-react-native-airwave)):
Gradle compiles its `android/` and Metro bundles its `src/`, so a pin change
needs neither a reinstall nor a prebuild. Its own Jenkins job
(`Jenkinsfile` in the Airwave repository) runs lint, typecheck and tests, and
archives the npm package (`react-native-airwave.tgz`) for each commit.

### expo-dev-client in release builds

`expo-dev-client` is a normal dependency so dev clients can be produced. In
release builds the dev launcher/menu compile to the upstream no-op stubs —
`expo.devlauncher.configureInRelease` is never set, the Android release sources
use `src/disableInRelease`, and the iOS pods are `debugOnly` — so no developer
tooling ships. No action needed.

## iOS builds (EAS)

iOS is still built with [EAS Build](https://docs.expo.dev/build/introduction/)
(see `eas.json`), which needs an Apple signing identity and macOS toolchain:

```bash
eas build --profile development   # dev client (internal)
eas build --profile preview       # internal, Release device build
eas build --profile production    # App Store
```

Cloud builds need the licensed fonts via the `eas-build-pre-install` hook — set
`PROXIMA_NOVA_FONTS_URL` (a `.zip`) or `PROXIMA_NOVA_FONTS_DIR` as an EAS
secret/environment variable (`eas env:create … --visibility secret`). The
Android Jenkins pipeline does **not** need this.

Production artifacts are submitted with `eas submit`, or uploaded manually, as
`com.nessjs.animu`.

## Voice assistants

Siri (App Intents / App Shortcuts) and Google Assistant (App Actions) both open
the `animuapp://assistant/play` deep link, handled in
`src/core/assistant/assistant.service.ts`.

- Native entry points are generated by `plugins/withIOSAppIntents.js` and
  `plugins/withAndroidAppActions.js`.
- Localized Siri phrases live in `AppShortcuts.strings` (PT/EN/ES/JA).
- Google App Actions are ingested from `res/xml/shortcuts.xml` when a release is
  uploaded to the Play Console.
- The iOS assistant hint shows only the Siri phrase (no "Ok Google").
